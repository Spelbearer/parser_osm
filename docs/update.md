# Как обновить POI и Teradata

Инструкция для настроенной установки POI OSM 0.9.0rc14. Первичная установка и повторное согласование границ не требуются. Цель: получить свежий снимок OSM, проверить его и синхронизировать Teradata. Состояние на 16.11.2026.

## 1. Открой PowerShell в проекте

Команды выполняй по одной, переходя к следующей только после успешного завершения предыдущей. Закрой открытые CSV/Parquet и слои Google Earth из папки результата, чтобы они не мешали замене файлов.

```powershell
cd "C:\Users\danila.kondratyev.T2RU\Desktop\test_sys\parser_osm"
```

## 2. Обнови код

git pull получает новую версию программы из GitHub. Это не обновление точек OSM и не загрузка в Teradata. Если Git сообщает ошибку, сначала устрани её. Python запускается напрямую из .venv: активация окружения не требуется.

```powershell
git pull
.\.venv\Scripts\python.exe run.py --version
```

## 3. Проверь настройки компьютера

Открой local.json. Для текущей структуры base_dir=".", product_folder="result": рабочая папка — parser_osm\result, готовый результат — parser_osm\result\result. При другом base_dir результаты будут там. Если local.json отсутствует, скопируй local.example.json в local.json и настрой его; существующий файл не перезаписывай.

На работе: proxy.enabled=true, url=http://t2rs-fgproxy.corp.tele2.ru:8080, windows_negotiate=true. Дома без прокси: proxy.enabled=false. publication.enabled=true означает автоматическую отправку KML после сборки; если хочешь проверить данные до отправки, поставь false и используй отдельную команду публикации. Пароли здесь не указываются.

В инструкции команды без --root: они используют local.json, включая прокси. Явный --root отключает чтение local.json.

```powershell
Get-Content .\local.json
notepad .\local.json
```

## 4. Получи свежие точки

Рекомендуемый вариант — скачать Geofabrik. Команда скачивает восемь PBF во временную папку, проверяет согласованность снимка, извлекает POI, сравнивает с прошлым реестром, строит круги, считает CNT_CIRCLE и формирует файлы. Временные данные удаляются после выполнения. Скорость зависит от сети и компьютера; ожидание может быть длительным.

Альтернатива: положи свежий полный набор PBF в input_folder, укажи source_mode="local" и выполни run.py без флагов. Все части должны относиться к согласованному снимку.

--files не получает свежие данные OSM: он только пересоздаёт файлы из уже сохранённого реестра. Используй его после изменения правил вывода или кругов, когда новый снимок не нужен.

```powershell
.\.venv\Scripts\python.exe run.py --download
```

## 5. Проверь итог сборки

Дождись SUCCESS / PRODUCT_SUCCESS и возвращения приглашения PS. При стандартном расположении открой сводку ниже: total_objects — число точек, unassigned_objects — без региона, kml_counts — круги, circle_membership — попадания в круги, temporary_files_removed — очистка временных файлов. Проверь, что количество объектов и регионов ожидаемое. CSV, Parquet, региональные части и poi_layers.zip находятся в result\result.

При ошибке сборки предыдущий успешный результат сохраняется. Не запускай загрузку, пока не разберёшь ошибку: иначе можно загрузить прежний успешный снимок.

```powershell
Get-Content .\result\result\analysis\summary.json -Raw
```

## 6. Проверь данные для Teradata

Команда проверяет полный CSV, уникальность, типы, даты, координаты, CNT_CIRCLE и длины текста; подготавливает очистку несовместимых символов. К серверу не подключается и данные не изменяет. Успех — TERADATA_CHECK_SUCCESS. Убедись, что в таблице уже есть CNT_CIRCLE INTEGER; создавать таблицу заново не нужно.

```powershell
.\.venv\Scripts\python.exe run.py --check-teradata
```

## 7. Загрузи изменения в Teradata

Нужны доступ к корпоративной сети, зависимости requirements-teradata.txt и пароль в POI_TD_PASSWORD либо keyring (сервис teradata). Загрузчик сравнит снимок с реальной таблицей SBX_OPERATION.DAK_POI_ISH: вставит новые, обновит изменившиеся, удалит отсутствующие ключи; остальным сбросит только RECORD_STATUS на UNCHANGED. Пакеты до 10 000 строк, один COMMIT после проверок. Строки awaiting COMMIT ещё не означают успешную загрузку. Дождись TERADATA_LOAD_SUCCESS.

Если счётчики CNT_CIRCLE заполняются впервые, обновлений может быть много даже при CSV UNCHANGED. При повторной загрузке одинаковых значений полные строки не пересылаются. Если потерян ответ при COMMIT, сначала проверь таблицу — исход может быть неопределённым. Отчёт: analysis/teradata_load.json, изменённые ключи: analysis/teradata_delta.csv.

```powershell
.\.venv\Scripts\python.exe run.py --load-teradata
```

## 8. Опубликуй круги, если нужно

Если автоматическая публикация выключена, отправь готовый ZIP в сетевую папку отдельной командой. Пересчёт кругов и PBF не требуются. По умолчанию папка: \\corp.tele2.ru\operations_MR\Operations_All\Потенциал_рынка. В сетевом архиве только KML, с именами макрорегион/EDW и согласованными исключениями. Успех — KML_PUBLISH_SUCCESS; отчёт — analysis/publication.json.

Если сеть недоступна, локальная сборка остаётся готовой. После восстановления сети повтори только --publish-kml. Если publication.enabled=true и отправка уже прошла после шага 4, повтор не нужен.

```powershell
.\.venv\Scripts\python.exe run.py --publish-kml
```

## 9. Очистка — при необходимости

После успешной сборки временные файлы уже удаляются автоматически. Отдельная команда нужна для старых распознанных артефактов и кэшей. Текущая выгрузка, .state, границы, настройки и входные PBF сохраняются. Неизвестные файлы не удаляются. Отчёт — result\logs\cleanup.json. Успех — PRODUCT_CLEAN_SUCCESS.

```powershell
.\.venv\Scripts\python.exe run.py --clean
```

## Если что-то пошло не так

Если команда долго работает, не запускай вторую копию. В отдельном PowerShell из папки проекта посмотри журнал:

```powershell
Get-ChildItem .\result\logs -Filter "product-*.log" | Sort-Object LastWriteTime -Descending | Select-Object -First 1 | Get-Content -Tail 40
```

Путь журнала предполагает base_dir="." и product_folder="result". Для загрузчика журнал — result/logs/teradata.log. При ошибке остановись на текущем шаге; следующий не выполняй автоматически. Реестр result/result/.state необходим для сравнения снимков — не удаляй его.

Зависимости устанавливают при первой настройке или изменении requirements, а не обязательно при каждом сборе. На корпоративном компьютере:

```powershell
.\.venv\Scripts\python.exe -m pip install --proxy "http://t2rs-fgproxy.corp.tele2.ru:8080" -r requirements.txt -r requirements-teradata.txt
```

Дома без прокси убери --proxy и адрес. Ошибки установки нужно устранить до запуска программы.
