# Один объект — одна строка

Основной `poi.csv` создаётся в каждом новом успешном FULL/INCREMENTAL/preview запуске. Ключ объекта — **osm_type + osm_id**, а не одно число: `node/123` и `way/123` могут быть разными точками. Для приложения используйте уникальный `osm_uid`.

Если объект подходит одновременно под `electronics` и `mobile_phone`, в CSV будет одна строка с `tag = electronics | mobile_phone`. Поля `osm_key`, `osm_value`, `category`, `subcategory`, `telecom_type`, `telecom_evidence` и `chain_evidence` также содержат объединённые уникальные значения через ` | `. В Excel для них используйте фильтр «Содержит»; `is_telecom` остаётся обычным признаком `1/0` и равен 1, если телефония есть хотя бы в одной категории объекта.

Новые поля:

| Поле | Значение |
|---|---|
| osm_uid | Уникальный идентификатор вида `node/123`, `way/123`, `relation/123` |
| tag_count | Число категорий исходного объекта |
| classifications | JSON-массив исходных соответствий: tag → osm_key/osm_value → category/subcategory, признаки телефонии/сети, даты наблюдения и статус каждой категории |
| primary_tag / primary_category / primary_subcategory | Единственное основное направление, выбранное по приоритетам телефонии |
| primary_osm_key / primary_osm_value | Исходная пара тега основной категории |
| primary_reason | Основание выбора основной категории |
| all_tags | Полный список тегов JSON-массивом |

`classifications` сохраняет точные связи между значениями, поэтому объединённые подписи не нужно разбирать для восстановления исходных категорий. Исходный `osm_id` сохраняется без замены на выдуманное число. Координаты, имя, регион, бренд и адрес у категорий одного объекта должны совпадать; противоречия блокируют экспорт, произвольная строка не выбирается.

Для сети выбирается единственное распознанное значение среди категорий. Несколько разных сетей или конфликт хотя бы в одной категории дают `chain_status=conflict`, без произвольного выбора сети. Конкретные кандидаты остаются в `classifications`. Даты наблюдения сводятся по активным категориям: earliest first_seen, latest last_seen; при разных статусах категорий агрегированный статус — UPDATED. Это представление текущих записей, а не отдельный механизм истории организаций.

Файлы нового запуска:

- `poi.csv` — все уникальные объекты, включая непривязанные;
- `poi_objects.parquet` — те же объекты и поля, включая непривязанные;
- `poi_teradata.csv`, `poi_teradata.parquet` — по одной основной категории на объект, только node/way по умолчанию, без объединённых `tag`/`category`; [правила приоритетов и схема](teradata.md);
- `objects/<region_code>.csv` — уникальные объекты региона;
- `objects/unassigned.csv` — объекты без однозначного региона;
- `poi_by_tag.csv` — подробные строки по тегам в режиме preview;
- `full/`, `delta/`, `all_russia.parquet` (в preview — `poi_assigned.parquet`) — прежний подробный формат по тегам.

Для фильтрации по утверждённому охвату требуются проверенные границы; новый формат не делает предварительную региональную привязку проверенной. Для статистики `metrics.unique_objects` — количество объектов в основном CSV, `metrics.category_rows` и прежнее `metrics.total` — число строк по тегам, `metrics.extra_category_rows` — их разница. Счётчики по тегам/категориям сохраняют прежний смысл. Объединение не уменьшает число уникальных организаций, поскольку один бизнес всё ещё может быть представлен отдельными node и way: это другая задача географической дедупликации.

## Уже готовая выгрузка: без повторного чтения PBF

Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m poi_osm.objects "D:\parser\parser_osm\preview\20261110T213831-2af06975"
```

Выберите свой каталог успешного запуска. Команда читает `preview.sqlite` или `registry.sqlite` только для чтения, не меняет исходные CSV и создаёт новую подпапку `unique-<время>-<идентификатор>` с `poi.csv`, `poi_objects.parquet`, `objects/` и отчётом `summary.json`. Можно передать путь к самому SQLite-файлу. Данные из FAILED/RUNNING запусков не конвертируются как завершённые. PREVIEW_INCOMPLETE разрешён с сохранением исходного статуса в отчёте; UNKNOWN при отсутствии исходного отчёта не подтверждает полноту.

В этой же папке создаются `poi_teradata.csv/parquet`. Правила основной категории читаются из `config/primary_selection.json`; можно передать альтернативный файл через `--priority-config`. Это пересчитывает только выбор основной категории, сохраняя все первоначальные теги и классификации.

Правила категорий при таком преобразовании не пересчитываются: сохраняется классификация исходной выгрузки. Чтобы применить изменённые справочники или извлечь новые типы POI, нужно заново обработать PBF. Внутренний реестр и дельты остаются уникальными по `(osm_type, osm_id, tag)`; категории не теряются и не превращаются в ложные удаления.
