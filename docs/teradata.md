# Выгрузка для Teradata

В `result/poi_teradata.csv`, `poi_teradata.parquet` и `regions/` одна строка соответствует одному OSM-объекту. Relations исключены только на выходе; полный исходный реестр сохраняет их для геометрий и актуализации.

По согласованному профилю остаются **18 колонок**:

```text
osm_type, osm_id, point_name, lon, lat, wkt, region_name, REGION_NAME_EDW,
primary_category, primary_subcategory, primary_osm_key, primary_osm_value,
is_telecom, telecom_type, is_chain, chain_name, update_date, record_status
```

`config/teradata_export.json` задаёт состав колонок. `osm_id_format: numeric_with_type` сохраняет исходный числовой ID; в Parquet — int64, в SQL-примере — BIGINT. Логический ключ и UNIQUE PRIMARY INDEX: **`(osm_type, osm_id)`**. `node/123` и `way/123` — разные объекты. Формат `typed` поддерживается как явная альтернативная настройка с текстовым ключом, но профиль поставки использует числовой ID и отдельный тип.

CSV: UTF-8 BOM, разделитель `;`, признаки `1/0`, пустое значение для NULL. Parquet: признаки boolean, даты DATE. Исходные метаданные, исключённые из схемы загрузки, остаются в `result/.state/registry.sqlite`.

## Основная категория

Если хотя бы одна категория относится к телефонии, выбор идёт среди таких категорий. Приоритет ремонта и порядок тегов находятся в `config/primary_selection.json`. Категория и подкатегория берутся из выбранного исходного тега; сеть определяется отдельно по всему объекту. Полные исходные соответствия не удаляются из реестра.

Смена приоритета может поменять основную категорию при прежнем `record_status=UNCHANGED`: исходные данные OSM при этом не менялись. Загрузчик применяет весь активный снимок независимо от этого статуса.

Проекция проверяет уникальность ключа, число строк/схему CSV и Parquet, согласованность региональных частей. Состояние обновления остаётся в полном реестре, поэтому сокращение выходных колонок не мешает следующей актуализации.

`region_name` формируется по столбцу EDW встроенного справочника. Географический ISO-код используется для сопоставления до сокращения колонок. У разных субъектов может быть одно операционное имя; оно не входит в ключ объекта. Обновление справочника может изменить `region_name` при прежнем record_status, поэтому загрузчик применяет полный снимок, включая строки UNCHANGED.

`REGION_NAME_EDW` — отдельная текстовая колонка непосредственно из EDW справочника регионов, сопоставляемая по ISO-коду. Для точек без региона значение пустое. Она добавляется также при пересоздании файлов с ранее сохранённым профилем. Существующая колонка `region_name` сохраняется.

## Загрузка SBX_OPERATION.DAK_POI_ISH

Загрузчик работает с уже созданной таблицей пользователя. [teradata_compact.sql](teradata_compact.sql) документирует её схему; приложение не выполняет CREATE/ALTER/DROP. В БД 19 колонок: 18 колонок экспорта и дополнительный `OSM_TYPE_ID = osm_type/osm_id`. PRIMARY INDEX этой MULTISET-таблицы не уникален: уникальность проверяется загрузчиком до отправки и запросом после вставки.

Установите необязательные зависимости (для корпоративного компьютера):

```powershell
.\.venv\Scripts\python.exe -m pip install --proxy "http://t2rs-fgproxy.corp.tele2.ru:8080" -r requirements-teradata.txt
```

Подключение: `teradatasql`, `host=td2800.corp.tele2.ru`, `logmech=LDAP`, `user=getpass.getuser()`. Сначала проверяется переменная `POI_TD_PASSWORD`, затем Windows keyring, сервис `teradata`, тот же логин. Для безопасного интерактивного сохранения пароля:

```powershell
$tdUser = .\.venv\Scripts\python.exe -c "import getpass; print(getpass.getuser())"
.\.venv\Scripts\python.exe -m keyring set teradata $tdUser
```

Не присылайте пароль в чат и не добавляйте в конфигурацию проекта. Загрузчик не записывает пароль в отчёты и маскирует его в ошибках драйвера.

Для фактического корня пользователя (внутри `parser_osm/result`):

```powershell
.\.venv\Scripts\python.exe run.py --root ".\result" --check-teradata
.\.venv\Scripts\python.exe run.py --root ".\result" --load-teradata
```

`--check-teradata` проверяет локальный CSV без соединения с БД. Проверяются PRODUCT_SUCCESS, production_ready, число строк, непустой снимок, уникальность ключей, BIGINT, координаты, даты, признаки, длины VARCHAR(255) для POINT_NAME и VARCHAR(100) для остальных текстовых полей. Проверяется приватная временная копия CSV, которая удаляется после выполнения. При превышении длины данные не обрезаются: команда указывает поле, строку CSV и ключ OSM. Нужно согласовать расширение соответствующей колонки таблицы; текущая версия рассчитана на заданный DDL с пределом 255 UTF-16 единиц для POINT_NAME и 100 для остальных текстовых полей. Координаты округляются до пяти знаков (ROUND_HALF_UP), IS_TELECOM передаётся числом, IS_CHAIN — строкой 0/1, пустые значения — NULL.

`--load-teradata` повторяет все проверки, затем открывает соединение. Используются ANSI-транзакция и `autocommit=False`. Проверяются целевые имена колонок и берётся WRITE-lock таблицы до DELETE. Далее **полностью заменяется содержимое** `DAK_POI_ISH` текущим активным снимком: executemany пакетами по 10 000, COUNT и COUNT DISTINCT OSM_TYPE_ID, один COMMIT. Ошибка до COMMIT вызывает ROLLBACK; промежуточных коммитов нет. Повторная успешная загрузка того же снимка не накапливает дубликаты. Другие таблицы не меняются. В рамках полной замены объекты, отсутствующие в новом активном снимке, исчезают из таблицы.

Отчёт последней проверки/загрузки — `result/analysis/teradata_load.json`, журнал последней попытки — `logs/teradata.log`. COMMIT с потерянным ответом сервера имеет неопределённый исход: сообщение требует проверить таблицу до повторной попытки. Автоматического повтора нет. Для работы необходим доступ к корпоративному серверу, права SELECT/DELETE/INSERT и достаточный spool/транзакционный ресурс на весь снимок. Пароль и соединение не требуются для предварительной проверки.
