# Выгрузка для Teradata

В `result/poi_teradata.csv`, `poi_teradata.parquet` и `regions/` одна строка соответствует одному OSM-объекту. Relations исключены только на выходе; полный исходный реестр сохраняет их для геометрий и актуализации.

По согласованному профилю остаются **17 колонок**:

```text
osm_type, osm_id, point_name, lon, lat, wkt, region_name,
primary_category, primary_subcategory, primary_osm_key, primary_osm_value,
is_telecom, telecom_type, is_chain, chain_name, update_date, record_status
```

`config/teradata_export.json` задаёт состав колонок. `osm_id_format: numeric_with_type` сохраняет исходный числовой ID; в Parquet — int64, в SQL-примере — BIGINT. Логический ключ и UNIQUE PRIMARY INDEX: **`(osm_type, osm_id)`**. `node/123` и `way/123` — разные объекты. Формат `typed` поддерживается как явная альтернативная настройка с текстовым ключом, но профиль поставки использует числовой ID и отдельный тип.

CSV: UTF-8 BOM, разделитель `;`, признаки `1/0`, пустое значение для NULL. Parquet: признаки boolean, даты DATE. Исходные метаданные, исключённые из схемы загрузки, остаются в `result/.state/registry.sqlite`.

## Основная категория

Если хотя бы одна категория относится к телефонии, выбор идёт среди таких категорий. Приоритет ремонта и порядок тегов находятся в `config/primary_selection.json`. Категория и подкатегория берутся из выбранного исходного тега; сеть определяется отдельно по всему объекту. Полные исходные соответствия не удаляются из реестра.

Смена приоритета может поменять основную категорию при прежнем `record_status=UNCHANGED`: исходные данные OSM при этом не менялись. Будущий MERGE должен обновлять совпавший ключ независимо от этого статуса.

## Граница будущего загрузчика

[teradata_compact.sql](teradata_compact.sql) — проект схемы, staging и MERGE для текущих 17 колонок. Он не исполняется приложением и должен быть согласован с целевой таблицей по вашим примерам. Старую таблицу SQL автоматически не удаляет.

Файлы содержат полный активный снимок. Категорийные DELETED во внутреннем реестре нельзя напрямую применять как удаление целого объекта: у него могла остаться другая категория. Отсутствие строки в произвольном staging само по себе не должно удалять данные. Логика загрузки, транзакции, история и применение объектных удалений будут реализованы отдельным этапом.

Проекция проверяет уникальность ключа, число строк/схему CSV и Parquet, согласованность региональных частей. Состояние обновления остаётся в полном реестре, поэтому сокращение выходных колонок не мешает следующей актуализации.
