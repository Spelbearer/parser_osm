# Категории, телефония и сети для адресной программы

Классификация добавляет поля, сохраняя исходные теги и идентификаторы. Она применяется в обычной выгрузке и в `poi_osm.preview`. Повторите обработку своего PBF после `git pull`, чтобы получить новые колонки. Старые результаты сохраняются. Основной `poi.csv` теперь объединяет категории одного OSM-объекта в одну строку: для `category`/`subcategory` используйте «Содержит», а `is_telecom` остаётся общим признаком. Подробные соответствия есть в `classifications`, детальные строки — в `poi_by_tag.csv` для preview и `full/`. См. [описание уникального формата](object-export.md).

| Поле | Значение и фильтр |
|---|---|
| category | Крупная группа: продукты, телефония, бытовые услуги, дом/ремонт, красота, ПВЗ и другие |
| subcategory | Вид деятельности: супермаркет, ремонт телефонов, салон связи и т. п. |
| is_telecom | В CSV `1` для распознанной телефонии и `0` для остальных строк; в Parquet boolean |
| telecom_type | Ремонт телефонов, салон связи, офис связи |
| telecom_evidence | `osm_tags` — явные теги; `name_hint` — текст названия; `chain_*` — распознанный оператор связи; `configured_indirect` — косвенная связь по справочнику |
| chain_id / chain_name | Стабильный код и отображаемое название сети |
| is_chain | `1` / true для распознанной сети; NULL для нераспознанных или конфликтных записей |
| chain_status | `identified`, `not_identified`, `conflict` |
| chain_evidence | Откуда получено совпадение: `brand:brand`, `operator:operator`, `name_hint:name` и т. п. При конфликте — кандидаты |
| brand / operator | Исходные OSM-значения для проверки результата |

Типовые фильтры в Excel:

- Все точки телефонии: `is_telecom = 1`.
- Ремонт телефонов: `telecom_type = Ремонт телефонов`.
- Исключить распознанные сети: оставить `chain_status = not_identified`; конфликтные строки проверить отдельно.
- Только Ozon/Wildberries: `chain_id` равен `ozon` или `wildberries`.
- Продуктовые сети: `category = Продукты питания`, затем выбор нужных `chain_name`.

Справочник `config/categories.json` задаёт группу и подкатегорию каждому разрешённому значению. `config/chains.json` содержит исходный список 35 сетей и варианты написания: Пятёрочка, Магнит, Перекрёсток, Дикси, Лента, Ашан, ВкусВилл, Ozon, Wildberries, Яндекс Маркет, СДЭК, МТС, МегаФон, Билайн, T2, DNS и другие. Это редактируемый список, а не полный реестр действующих сетей РФ. Пользовательские пути можно указать в settings через `categories` и `chains`, относительно `project_root`.

Отдельный файл **`config/telecom.json`** управляет включением направлений в телефонию. `direct_tags` содержит профильные значения, а `indirect_tags` — `electronics`, `electronics_repair`, `computer`, `repair`. Все они получают `is_telecom=1` без дополнительных условий по названию. Для косвенных направлений `telecom_evidence=configured_indirect`, а `telecom_type` содержит отдельную подпись, например «Компьютеры (косвенная связь)». Это расширенный коммерческий охват по решению пользователя, а не утверждение, что любой компьютерный магазин ремонтирует телефоны.

Для изменения достаточно открыть JSON в Блокноте, добавить/удалить ключи или изменить русские подписи. Поле `category` задаёт название группы телефонии, `labels` — уточняющие названия ремонта телефонов, салонов и офисов связи. Правила телефонии приоритетнее общей категории из `categories.json`; чтобы убрать косвенное направление из телефонии, удалите его ключ из `indirect_tags`. Для этой строки вернётся базовая группа из `categories.json`; другой профильный тег того же OSM-объекта может по-прежнему давать строку телефонии. Чтобы полностью исключить направление из выгрузки, меняйте `tag_mapping.json`. Добавление значения только в справочник телефонии не расширяет набор извлекаемых OSM-тегов.

```json
"indirect_tags": {
  "electronics": "Электроника (косвенная связь)",
  "electronics_repair": "Ремонт электроники (косвенная связь)",
  "computer": "Компьютеры (косвенная связь)",
  "repair": "Ремонт и сервис (косвенная связь)"
}
```

Это фрагмент внутри файла, а не отдельный полноценный JSON. Редактируйте существующий файл, сохраняя кавычки и запятые; после правки нужно повторно обработать PBF. Альтернативный путь можно указать в settings полем `telecom`, относительно `project_root`.

Приоритет распознавания: `brand`, затем `operator`, затем `name`, `name:ru`, `official_name`. Учитываются регистр, «ё/е», кавычки и знаки препинания; совпадения не ищутся внутри слов. Распознавание по названию ограничено подходящими типами объектов, например WB распознаётся в ПВЗ/постаматах, а «Магнит» — в продуктовой торговле и косметике. Несколько сетей на одном уровне доказательств дают `conflict`, произвольная сеть не выбирается.

Совпадение названия — подсказка для проверки, особенно для общих слов «Лента», «Верный», «Магнит». Структурированный `brand` имеет больший приоритет, но также зависит от качества OSM. Отсутствие совпадения не доказывает независимость бизнеса, а наличие марки сети не определяет владельца, франчайзинг, активность точки или полномочия по заключению договора. Классификация помогает сформировать список для проверки продажниками, не заменяя её.

Внутри широкого охвата точные профильные теги, `mobile_phone:repair=yes/only`, `repair=mobile_phone` и названия о ремонте телефонов/смартфонов уточняют подтип. Оператор связи может уточнить категорию магазина электроники. Компьютерный сервис без таких признаков входит в косвенную телефонию, но не получает подтип «Ремонт телефонов». Объекты без подходящей OSM-категории не добавляются только из-за похожего названия. Мультикатегорийный POI остаётся несколькими строками; статистика считает строки, не уникальные организации.

В summary/log теперь есть количество строк по бизнес-категориям и сетям и `telecom_total`. Эти признаки не удаляют точки автоматически. Кластеризация территорий/маршруты выездов пока не добавлены.

Изменились фильтры и схема данных. Обычный FULL/INCREMENTAL не сравнивает новый формат со старым успешным реестром: для новой исходной версии используйте отдельный `project_root` с копией конфигурации и согласованных границ, сохраняя старые результаты. Это защищает от ложных удалений при изменении охвата. Режим preview каждый раз создаёт отдельную папку и продолжает работать без такой миграции.
