# Ежемесячный запуск в Windows

Временные индексы libosmium находятся отдельно в `work/temporary/indexes`. Библиотека может удерживать их до завершения процесса; при WinError 32/33 удаление откладывается с записью в журнал, не прерывая успешную обработку. Следующий запуск удалит оставшиеся индексы после освобождения файлов. Ошибки чтения, геометрии и доступа к самим данным продолжают блокировать публикацию.

Сначала выполните установку и полный успешный ручной запуск в каталоге `C:\OSM_POI`. Учётная запись задачи должна иметь чтение исходных данных/конфигурации, запись в `source`, `work`, `output`, `state`, `logs` и сетевой доступ к выбранному источнику. Пароли не записываются в команду или конфигурационные файлы проекта.

В Планировщике заданий создайте задачу:

* Триггер: ежемесячно, первый день, 02:00 по часовому поясу компьютера.
* Действие «Запуск программы»: `C:\OSM_POI\.venv\Scripts\python.exe`.
* Аргументы: `"C:\OSM_POI\main.py" --config "C:\OSM_POI\config\settings.json" --mode full --force-download`.
* Рабочая папка: `C:\OSM_POI`.
* Правило при уже работающей задаче: не запускать новый экземпляр.
* Включите запуск пропущенного задания при первой возможности. Ограничение длительности задавайте по измеренному полному запуску; произвольный короткий тайм-аут может оборвать обработку России.

Если консоль не должна появляться, используйте `C:\OSM_POI\.venv\Scripts\pythonw.exe` с `main.pyw` и теми же аргументами. Логи пишутся в файлы; окно терминала для диагностики не требуется. Основной процесс возвращает `0` при успехе и ненулевой код при ошибке. Не запускайте обёртку через `start` или `Start-Process` без ожидания: тогда Планировщик может увидеть успех запуска оболочки вместо результата выгрузки.

Пример регистрации через PowerShell, выполняемый пользователем после проверки путей:

```powershell
$poiAction = New-ScheduledTaskAction `
  -Execute 'C:\OSM_POI\.venv\Scripts\python.exe' `
  -Argument '"C:\OSM_POI\main.py" --config "C:\OSM_POI\config\settings.json" --mode full --force-download' `
  -WorkingDirectory 'C:\OSM_POI'
$poiSettings = New-ScheduledTaskSettingsSet -StartWhenAvailable -MultipleInstances IgnoreNew
```

`New-ScheduledTaskTrigger` не предоставляет универсального месячного параметра во всех версиях модуля; месячный триггер задайте в интерфейсе Планировщика. Приведённые объекты действия и параметров можно использовать при ручной регистрации/импорте задачи. Не подменяйте ежемесячный триггер ежедневным без явного решения.

После настройки запустите задачу вручную через Планировщик. Проверьте «Результат последнего запуска», свежий журнал и изменение нужного `last_success.json`. При ошибке исходный успешный указатель должен остаться прежним. Наличие процесса или CSV-файла во временном каталоге само по себе не доказывает успешную публикацию.

Системный сон, перезагрузка и работа от батареи регулируются параметрами Планировщика, а не Python-кодом. Для больших PBF предпочтителен локальный SSD. При запуске от другой учётной записи используйте абсолютные пути и её действующие права/прокси; интерактивные сетевые диски могут быть недоступны.

Задача не регистрируется приложением автоматически. Настройка расписания и её проверка на Windows требуют доступа к целевому компьютеру; эти действия не выполнялись в облачной Linux-среде.
