# Проверка выпуска 0.9.0rc10

Выпуск содержит производственный экспорт POI/KML; загрузчик полного снимка в Teradata реализован с отдельной командой. Форматы реестра и итоговых 18 колонок совместимы с предыдущей производственной версией.

Автоматические проверки:

```text
python -m ruff check .
python -m pytest -q
python run.py --version
```

Тестируются фактические пути новой установки, миграции, обычного обновления и `--files`; разбор node/way/relation, классификация, основной тег, уникальность составного ключа, first_seen и tombstones, качество и источники, аудит CSV/Parquet, точность радиуса KML/антимеридиан, CRC ZIP, очистка, блокировки и откат публикации. Общие фикстуры вынесены из исполняемых тестовых модулей.

Удалены сценарии устаревших одиночных CLI/preview, а применимые проверки перенесены на текущую сборку. Количество тестов не является сравнением полноты разных версий; результат актуального запуска фиксируется в CI. Матрица CI: Windows/Linux × Python 3.11/3.13.

При ревизии канонический CSV до и после упрощения экспортера сравнивался побайтно на синтетическом реестре с несколькими категориями и коллизией числовых ID node/way; содержимое совпало. Изменение структуры кода не требует нового baseline данных.

Для пользовательского запуска проверьте `result/analysis/summary.json`, `audit.json`, `cleanup.json`, `regions_index.csv`, `kml_summary.json`. Статус должен быть PRODUCT_SUCCESS, проверки файлов — успешными, временные данные — удалёнными. Непривязанные точки анализируются по review.csv, неизвестные файлы очистка сохраняет.

На реальном пользовательском наборе предыдущая версия обработала 433 564 объекта для загрузки и создала 75 311 кругов/356 436 названных точек. Эти числа описывают тот снимок, а не обязательные значения для будущих обновлений. Полный российский набор и Windows-планировщик в облачных тестах не воспроизводятся; SQL-пример на Teradata не выполнялся.

Справочник EDW проверяется по всем 83 ISO-кодам. Интеграционная проверка подтверждает одинаковые операционные имена у разных субъектов, сохранение всех строк при FLAG=0, согласованность CSV/Parquet/KML и неизменность географического реестра, отпечатков и first_seen. Последующее обновление того же снимка сохраняет UNCHANGED.

Загрузчик тестируется на подставном DB-API соединении: 10 000+1 строк, LDAP/ANSI, COMMIT/ROLLBACK, ошибка схемы/вставки/количества, маскирование пароля, ограничения DDL и режим проверки без сети. Доступ к корпоративной Teradata из облачной среды отсутствует; реальная загрузка требует проверки на рабочем компьютере.

Проверяются согласованная очистка Unicode только в копии для вставки, fallback названия на primary_subcategory, сохранение исходного CSV, UTF8/UPT до DELETE, отказ UPT до изменения данных, диагностический CSV, чтение ошибок пакета до ROLLBACK и маскирование секрета в деталях драйвера. Реальная совместимость Unicode Pass Through с сервером пользователя требует запуска в корпоративной сети.

Режим visit_zones проверяется на компактной группе, группе с центром между POI, длинной улице, повторяющихся названиях, переходе ±180°, счётчиках телефонии/сетей и старой конфигурации без новых полей. Проверяются радиус каждого сохранённого состава, подавление по общим объектам и сохранение всех названных точек в отдельном слое.

Публикация проверяется при постоянном и временном запрете переименования, отказе обратного переименования и восстановлении по журналу. Экспорт выполняется дочерним процессом; ошибка профиля в дочернем процессе сохраняет предыдущие CSV и SQLite. Реальные корпоративные ACL/антивирус пользователя в облаке не воспроизводятся.

Автозагрузка проверяется на восьми маленьких настоящих PBF с HTTP doubles, едином наборе дат и MD5, отказе неправильного охвата, сохранении прежнего результата и удалении частичных загрузок при HTTP-сбое. Интеграционная проверка запускает обработчики PBF/экспорта и подтверждает сохранение remote URL и downloads.json после --files. Реальные запросы к Geofabrik из облака блокируются прокси; полный сетевой набор РФ здесь не скачивался.

Windows proxy transport проверяется подставным процессом curl: параметры SSPI/HTTPS/Schannel, валидация настоящего маленького PBF и MD5, удаление временных ответов, запрет HTTP-редиректа, очистка при прерывании и отсутствие stderr с данными авторизации в ошибках. Пользователь подтвердил получение MD5 с корпоративного прокси через curl/Negotiate/--ssl-revoke-best-effort; реальная загрузка всего набора этим транспортом в облаке не выполнялась.

Переносимость проверяется переименованием всей установки в путь с кириллицей: --files работает без старого расположения, а последующая сборка сохраняет контракт и UNCHANGED. Проверяются копирование исходных байтов правил, идемпотентность перехода v1→v2, выбор режима из local.json, приоритет --files, включение/выключение прокси без изменения внешнего окружения и отказ относительных путей, выходящих за base_dir.
