# Проверка выпуска 0.9.0rc1

Выпуск содержит производственный экспорт POI/KML; загрузчик в саму Teradata ещё не реализован. Форматы реестра и итоговых 17 колонок совместимы с предыдущей производственной версией.

Автоматические проверки:

```text
python -m ruff check .
python -m pytest -q
python run.py --version
```

Тестируются фактические пути новой установки, миграции, обычного обновления и `--files`; разбор node/way/relation, классификация, основной тег, уникальность составного ключа, first_seen и tombstones, качество и источники, аудит CSV/Parquet, точность радиуса KML/антимеридиан, CRC ZIP, очистка, блокировки и откат публикации. Общие фикстуры вынесены из исполняемых тестовых модулей.

Удалены сценарии устаревших одиночных CLI/preview, а применимые проверки перенесены на текущую сборку. Количество тестов не является сравнением полноты разных версий; результат актуального запуска фиксируется в CI. Матрица CI: Windows/Linux × Python 3.11/3.13.

При ревизии канонический CSV до и после упрощения экспортера сравнивался побайтно на синтетическом реестре с несколькими категориями и коллизией числовых ID node/way; содержимое совпало. Изменение структуры кода не требует нового baseline данных.

Для пользовательского запуска проверьте `result/analysis/summary.json`, `audit.json`, `cleanup.json`, `regions_index.csv`, `kml_summary.json`. Статус должен быть PRODUCT_SUCCESS, проверки файлов — успешными, временные данные — удалёнными. Непривязанные точки анализируются по review.csv, неизвестные файлы очистка сохраняет.

На реальном пользовательском наборе предыдущая версия обработала 433 564 объекта для загрузки и создала 75 311 кругов/356 436 названных точек. Эти числа описывают тот снимок, а не обязательные значения для будущих обновлений. Полный российский набор и Windows-планировщик в облачных тестах не воспроизводятся; SQL-пример на Teradata не выполнялся.
