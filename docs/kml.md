# KML: зоны посещения и точки POI

Пересоздание ZIP из сохранённого реестра без PBF и подключения к Teradata:

```powershell
git pull
.\.venv\Scripts\python.exe run.py --root ".\result" --files
```

При таком корне готовый ZIP находится в `result/result/poi_layers.zip`, отчёт — в `result/result/analysis/kml_summary.json`. В общем случае это `<root>/result/poi_layers.zip`. Хранится последний успешный результат, распакованные KML и временные базы удаляются после проверки ZIP. Настройки действующей установки — `<root>/config/kml.json`; файл проекта `config/kml.json` служит шаблоном для новых установок.

В архиве:

```text
layers/circles/RU-MOW_Москва_001.kml
... отдельные файлы по регионам и части ...
regions_index.csv
config.json
summary.json
```

## Зоны посещения

По умолчанию `circle_mode: visit_zones`:

1. Отбираются node/way с названием и регионом. Учитываются все категории и крупные сети. Имена сравниваются с учётом регистра после удаления крайних пробелов.
2. Возле каждой уникальной позиции POI проверяется локальное окружение. Кандидаты рассчитываются из положения POI и среднего пространственного центра соседей в пределах двух радиусов. Среднее определяется на сфере, включая переход через ±180°.
3. Состав уточняется до четырёх раз: точки ищутся вокруг нового центра, а центр пересчитывается по группе. Используется последнее допустимое положение центра. Каждый сохранённый состав повторно проверяется по WGS84: **все его точки находятся строго ближе 60 м от центра**, разных названий не меньше пяти. Не требуется, чтобы центр совпадал с магазином. В подсчёт входят все подходящие объекты внутри этого круга.
4. Совпадающие составы кандидатов объединяются. Затем кандидаты рассматриваются по убыванию количества разных названий, числа объектов и числа точек телефонии. При `count_mode: objects` число объектов становится первым критерием. Равенства разрешаются детерминированно.
5. Если с уже принятой зоной совпадает **не менее 80% объектов меньшей группы**, кандидат пропускается. Иначе зона сохраняется. Подмножество уже принятой группы не создаёт дополнительную зону. Сравниваются OSM-объекты, а не площади кругов или только названия.

Группы не объединяются транзитивно. На длинной улице возникают несколько компактных зон; большого круга по цепочке пересечений не появляется. Соседние зоны могут пересекаться, а отдельные POI могут входить в несколько зон. Это локальный эвристический поиск и жадный отбор; он не гарантирует математически минимального количества кругов или нахождения всех возможных групп. Не каждая точка обязательно входит в принятую зону.

Порог пяти **разных названий** сохраняется: пять одинаково названных филиалов дают одно название. Радиус 60 м относится к расстоянию от центра, а не к расстоянию любой пары магазинов. Максимальное расстояние между двумя участниками может приближаться к 120 м.

В подписи зоны указаны три количества: точек, точек крупных сетей и точек телефонии. В описании и ExtendedData только пять полей: эти три количества, регион и радиус. Технические идентификаторы, координаты центра, количество разных названий и способ подсчёта не выводятся; порог разных названий и расчёт геометрии сохраняются.

Границы регионов круг не обрезают: в состав могут входить POI соседнего региона. Зона записывается в регион ближайшего к её центру участника; это правило назначения файла, а не пространственное определение региона самого центра. Регионы с одинаковым EDW остаются отдельными по ISO-коду.

## Точки

По умолчанию `export_points: false`: отдельного слоя точек, папки layers/points и пустых файлов этого слоя в ZIP нет. Все исходные CSV/Parquet сохраняются для Teradata и последующей самостоятельной генерации точек. Для расчёта зон POI по-прежнему используются. В отчёте points_exported/kml_points=0, eligible_points и points_in_selected_circles отражают участие POI в расчёте.

При явном `export_points: true` создаётся опциональный слой. `points_scope: all_named` сохраняет все подходящие названные точки, включая одиночные; `selected_circles` — только точки внутри принятых зон.

В точках доступны название, OSM-тип/ID, категории, телефония, сеть и другие доступные поля источника. Все точки обозначены голубыми капельками `http://maps.google.com/mapfiles/kml/paddle/ltblu-blank.png`; кончик значка привязан к координате POI. Признак телефонии остаётся в атрибутах. Зоны имеют оранжевую полупрозрачную заливку. Текст XML экранируется.

## Настройки

| Параметр | По умолчанию | Значение |
|---|---|---|
| circle_mode | visit_zones | Зоны групп; `per_point` возвращает прежние круги вокруг POI |
| radius_m | 60 | Радиус в метрах, от >0 до 10 000 |
| min_count | 5 | Минимальное число названий/объектов |
| count_mode | distinct_names | Разные названия; `objects` — число объектов |
| zone_overlap_threshold | 0.8 | Доля общих объектов от размера меньшей группы для подавления кандидата; от >0 до 1 |
| export_points | false | Формировать отдельный слой точек |
| points_scope | all_named | Все подходящие названные точки; `selected_circles` — внутри принятых зон |
| circle_vertices | 72 | Число вершин полигона круга |
| max_features_per_file | 10000 | Лимит объектов на файл KML |
| osm_types | node, way | Типы объектов источника |
| include_unassigned | false | Включать точки без региона |
| telecom_only | false | Учитывать только телефонию |
| exclude_chains | false | Исключать крупные сети |
| regions | null | Все регионы; либо список ISO-кодов |

В старых файлах без `export_points` слой точек также выключен. В старых файлах без `circle_mode` автоматически используется `visit_zones`, без `zone_overlap_threshold` — 0.8. Явный `per_point` сохраняет прежнюю логику. При смене режима, параметров или версии отрисовки старый ZIP не переиспользуется; повторная сборка с тем же эффективным конфигом может использовать проверенный архив. Фильтры применяются до расчёта групп.

## Геометрия, проверки и ресурсы

Расстояния и вершины кругов рассчитываются по WGS84 через `pyproj.Geod`. Координаты не округляются до трёх знаков. По умолчанию отображаемый круг — полигон из 72 вершин, отклонение хорды при радиусе 60 м около 6 см. При пересечении ±180° геометрия разделяется. POI выше 89,9° широты отклоняются.

Отчёт содержит `zone_candidates`, `near_duplicate_zones_removed`, число принятых кругов, точек внутри них и всех экспортированных точек. `candidate_centers` считает исходные уникальные положения, а не итоговые зоны. KML проверяются XML-разбором и пересчётом Placemark, ZIP — по CRC и составу. Предыдущий успешный результат сохраняется при ошибке.

Полные свойства и кандидаты хранятся во временном SQLite; координаты и STRtree — в памяти. Сравнение зон использует индекс участников, а не все пары кругов. Очень плотные районы требуют больше вычислений. Синтетический расчёт групп для 10 000 точек в 1 000 разнесённых группах дал 1 000 зон примерно за 1,8 с с пиком RSS около 56 МиБ в облачном Linux (без записи KML/ZIP). Это не замер полного набора РФ или рабочего Windows.

Самостоятельный вспомогательный экспорт остаётся доступен через `python -m poi_osm.kml <completed_run> --output <folder> --config <json>`. У сокращённого источника без ISO-кода неоднозначные одинаковые названия регионов отклоняются; основной `run.py --files` использует полный внутренний источник.
